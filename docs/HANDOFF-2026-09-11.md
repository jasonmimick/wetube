## Why this happened

Vercel emailed: *"used 75% of the included free tier usage for Fluid Active
CPU"* on the Hobby plan. At 100% Vercel pauses projects, which would take
wetube offline including on a Sunday.

Cause: the church-PC agent polled `/api/agent/poll` every 3 seconds around
the clock — ~28,800 requests/day, ~864k/month — to catch 1–2 Masses a week.
wetube was **91.2% of all Fluid usage across the account's 14 projects**;
nothing else was close. Account-wide Edge Requests were 782k/1M, essentially
all of it this one loop.

This is the second outage from the same poll loop. The 2026-08-10 Firestore
fix throttled the heartbeat *write* and worked; it did not address the HTTP
request itself, which is what broke this time. See `AGENTS.md` Gotchas.

## Open questions

- **Did the 2026-09-06 Mass actually stream?** Broadcast History shows
  `3 min · 0 views`, against a Sep 2 test at `15 min · 11 views`. Two
  readings: (a) it streamed and nothing told YouTube to stop, or (b) vMix
  never pushed video and the broadcast sat in `ready` forever. (b) is the
  worse case — it means that Sunday did not stream at all — and
  `completeBroadcast()` would *not* fix it, since `ready` → `complete` is
  rejected by the API; such a broadcast has to be deleted. The stuck

## Operational notes

- **`vercel env pull` returns empty values** for this project's secrets —
  they are marked sensitive, so the CLI hands back `""` for
  `GOOGLE_OAUTH_*`, `TURSO_*`, everything. You cannot run YouTube or Turso
  scripts locally against production this way. To act on YouTube
  server-side, add an owner-only route that calls into `lib/youtube.ts`.
- **SmartScreen fires on every release.** The `.exe` is unsigned and `pkg`
  bundles a Node runtime, so each build is an unknown hash with no
  reputation. "More info → Run anyway" each time. An antivirus *folder*
  exclusion does not suppress SmartScreen — it is a separate system. Real
  cures: code signing, or dropping the packaged `.exe` and running
  `node agent.js` from a signed Node install.
- **Vercel log output lags.** A 60–75s gap with no new poll usually means
  the log query hasn't caught up, not that the agent died. Re-query before
  concluding anything.
- **The browser is a real cost.** `/api/state` polls every 5s while visible;
  a tab left open all day was 17.3k requests/day, more than the agent now
  costs. Fixed, but any new polling hook needs the same treatment.
